1. Resumen Ejecutivo y Objetivos del Proyecto

Ether es una solución web Fullstack concebida para la presentación formal de competencias técnicas, catálogo de servicios profesionales y demostraciones prácticas de proyectos. El sistema fue desarrollado bajo una arquitectura desacoplada cliente-servidor, orientada a cumplir con rigor los requisitos de evaluación y promoción de la cátedra mediante la implementación de operaciones CRUD completas, roles diferenciados de usuarios, gestión de consultas bidireccionales y analíticas en tiempo real.

🎯 Showcase Profesional Dinámico
Presentación interactiva de proyectos y servicios con carrusel automatizado, filtrado reactivo por tecnologías y control de errores en imágenes.
🔐 Control de Acceso por Roles (RBAC)
Privacidad estricta para el repositorio y especificaciones de código, accesibles únicamente por usuarios debidamente registrados en el sistema.
📨 Gestión de Consultas Bidireccional
Recepción de mensajes de contacto con despacho por Nodemailer y auditoría en la bandeja de usuario /mis-consultas bajo modelo estricto 1:1.
📊 Administración Integral y Métricas
Panel administrativo con gráficos Recharts interactivos, contadores de tráfico en vivo y gestión de seguridad contra autobloqueo de administrador.

2. Arquitectura del Sistema y Tecnologías

El diseño adopta una arquitectura en tres niveles con responsabilidades estrictamente desacopladas, comunicándose a través de una API REST protegida por tokens JWT:

┌─────────────────────────────────┐ HTTP / REST (JSON) ┌──────────────────────────────────┐ │ Frontend SPA (Cliente) │ ◄──────────────────────────────────► │ Backend API (Servidor) │ │ React 18 + Vite + Tailwind │ Cabeceras Authorization: │ Node.js 24 + Express 4 │ │ React Router 6 + Recharts │ Bearer <JWT> (HS256) │ Controladores / Middlewares │ └─────────────────────────────────┘ └────────────────┬─────────────────┘ │ better-sqlite3 ┌────────────────▼─────────────────┐ │ Base de Datos Local (SQLite) │ │ Modo WAL • Foreign Keys Activas│ └──────────────────────────────────┘
Componente Tecnología Rol y Justificación Técnica
Frontend React 18, Vite 6, Tailwind CSS Renderizado SPA reactivo, compilación nativa ultrarrápida y paleta oscura Ether sin CSS propietario.
Navegación React Router 6 Rutas públicas, privadas (ProtectedRoute) y redirección automática según rol.
Backend Node.js 24, Express 4 API REST por capas: enrutamiento, controladores, middlewares de rol y servicios desacoplados.
Persistencia SQLite (better-sqlite3) Motor relacional nativo sincrónico, con modo WAL de alto rendimiento y cero configuración externa.
Seguridad JWT + bcryptjs (Salt = 10) Autenticación stateless y almacenamiento seguro de contraseñas mediante hashing unidireccional.
Visualización Recharts SVG Gráficos interactivos de barra y área para la evolución de registros y consultas.

3. Modelo de Datos y Seguridad (RBAC)

La base de datos SQLite almacena 5 entidades normalizadas con integridad referencial y claves foráneas activas:

Tabla Campos Clave Propósito y Reglas de Integridad
users id, name, email (UNIQUE), password_hash, role, created_at Usuarios del sistema. Control de roles e índices únicos para autenticación rápida.
projects id, title, description, technologies, is_published, image_url Showcase técnico. Alimenta tanto el carrusel de inicio como el catálogo privado.
services id, title, description, icon, is_published Oferta técnica. Iconos dinámicos resueltos en cliente mediante IconResolver.
contact_messages id, user_id (FK), name, email, inquiry_type, message, status, response_message Buzón de consultas. ON DELETE SET NULL preserva mensajes al borrar un usuario.
site_metrics metric_key (PK), count, updated_at Telemetría: contadores atómicos de visitas_generales y accesos_autenticados.

Matriz de Roles y Niveles de Acceso

Rol Identificador Privilegios y Accesos en el Sistema
Visitante anonimo Acceso público a la portada, carrusel, servicios, vista previa y envío de consultas.
Usuario Normal usuario_normal Acceso al catálogo privado /proyectos, detalles técnicos y bandeja /mis-consultas.
Operador operador Bandeja de consultas /operador, auditoría de mensajes y envío de respuestas oficiales.
Administrador administrador Control total en /admin: CRUD de proyectos, servicios, gestión de usuarios y telemetría.

Salvaguardas de Integridad y Robustez

  • Prevención de Autobloqueo: El sistema bloquea programáticamente cualquier intento de un administrador de eliminar su propia cuenta en sesión o degradar/eliminar al último administrador registrado.
  • Invariante de Trazabilidad: La eliminación de un usuario no elimina sus mensajes; se conservan con user_id = NULL para auditoría contable y de soporte.
  • Inmunidad ante Inyecciones SQL: Todas las consultas en SQLite utilizan parámetros vinculados (prepared statements) asegurando inmunidad contra vectores maliciosos.
Principio de Privacidad: Las contraseñas se almacenan exclusivamente como hashes irreversibles generados con bcryptjs (10 rondas de salt). En ninguna respuesta de la API REST se expone el campo password_hash.

4. Módulos y Funcionalidades Destacadas

🎠 Carrusel de Proyectos (ProjectCarousel)
Componente interactivo en la cabecera conectado en tiempo real a SQLite. Cuenta con auto-play cada 5 segundos, pausa al situar el cursor, navegación manual por flechas y bullets de posición activa.
✨ Pie de Página Profesional (Footer)
Rediseño en 4 columnas (Identidad y estado en Localhost, Navegación rápida, Stack Tecnológico y Conectividad REST) con halo difuminado Ether y botón con scroll suave hacia el tope de la página.
📬 Bandeja de Usuario (/mis-consultas)
Espacio personal de auditoría para usuarios autenticados. Implementa el modelo estricto de 1 consulta : 1 respuesta definitiva registrada por el operador, evitando discusiones recursivas.
🛠️ Panel de Gestión Administrativa (/admin)
Consola central con gráficos Recharts interactivos, modales para alta/edición de proyectos y servicios con previsualización de iconos Lucide, y administración segura de roles de usuarios.

El proyecto Portfolio Profesional Ether cumple satisfactoriamente con la totalidad de los requisitos funcionales, no funcionales y de seguridad exigidos por la cátedra.
